# Framecheck 1.2｜Figma 視覺稿與網頁比對工具

純網頁、繁體中文、圖片在瀏覽器本機處理。無需擴充功能、Python、MCP 或外部 AI API。

## 開始使用

- **離線：** 直接用桌面 Chrome／Edge 開啟 `offline.html`，約 11 MB，已內嵌 OpenCV 與 WebAssembly，不需伺服器或網路。
- **網站：** 部署 `index.html` 與完整 `vendor/` 資料夾，辨識時只讀取同站 OpenCV 檔案。GitHub Pages 與內網靜態主機均適用。
- 單獨開啟 `index.html` 仍可手動比對；自動辨識請使用 offline.html 或 HTTP(S) 網站。

圖片只在分頁及 Worker 記憶體中處理，不上傳、不寫入 localStorage 或 IndexedDB，重新整理即清除。不使用 CDN、遠端字型或追蹤。OpenCV 固定為 4.13.0，來源、校驗碼與授權見 [vendor/README.md](vendor/README.md)。企業政策若禁止其運算程式編譯，仍可使用手動比對。

## A．首次設計驗收

1. 加入 Figma PNG 與網頁截圖，支援上傳、拖放、貼上；瀏覽器允許時可分享分頁擷取。貼上前先選擇目的地。
2. 按「① 選設計稿元件」框選目標；若已匯出單一元件，直接使用整張。
3. 按「自動尋找」，在整張原始網頁截圖尋找內容。也可用「② 選網頁元件」粗框區域，再勾選限制搜尋。
4. 點選候選卡，檢視框線及 50% 疊圖。可拖曳修正位置、輸入座標、調整倍率或外擴比較邊界。
5. 明確按「確認並套用對齊」後才改變畫布，不會自動核准驗收。
6. 使用並排、疊圖、滑桿及差異圖檢查；必要時設定比較範圍與忽略區，匯出 PNG／JSON。

原有裁切框支援輸入寬高並固定尺寸拖曳，需要重畫時取消鎖定。

### 倍率與座標

- **自動視覺對齊：** 搜尋網頁相對設計圖片的 0.25～4 倍尺度。估測倍率僅供視覺檢查，不能推定 CSS 尺寸。
- **固定倍率驗收：** 輸入網頁圖片像素 ÷ 設計圖片像素，只搜尋位置。例如網頁 800 px、設計圖 1000 px，填 0.8。允許 0.1～8。
- 套用後，同一對圖片後續搜尋固定此倍率，估測來源標記仍保留；替換圖片會清除舊候選及已確認倍率。
- 手動面板的「匯出倍率」是圖片像素／CSS px，與自動面板的網頁／設計圖片比例不同。自動結果不會將未知 CSS 倍率標為已知。
- 預覽 X/Y、報告中的設計框、網頁對應框及搜尋框，都是原始圖片座標。比較畫布像素受 Figma 匯出倍率設定影響。
- 原圖保持完整，每次從原圖產生比較影像。只等比例縮放及平移，不旋轉、不透視、不分別拉伸長寬。

### 背景、局部與缺圖

只排除選定範圍外背景；元件內底色、邊框與留白仍比較。外擴邊界可查看陰影或過大內容，最多擴到設計原圖邊界，不會生成原圖外的內容。

局部對齊不驗證元件在整頁的位置。整頁模式需至少 3 個有特徵的分散區塊支持同一組變換；響應式重排時應以對應視窗寬度重新擷取，或改成局部比對。

灰階及邊緣圖只用於定位，最後差異使用原始彩色圖。最多提供 3 個候選，匹配指標不是成功機率或設計還原度。純色、重複圖樣、動態內容或過小局部可能需要手動對齊；部分截圖只有足夠共同區塊時才能自動定位。

未擷取／單側無對應區域在差異圖以斜線表示，自動對齊的其他檢視也標示網頁缺失範圍。缺失像素分開統計，不放入差異比例分母。覆蓋不完整時停用整張基準核准，即使忽略缺失區也不會解除自動對齊的覆蓋限制。

### 數值與報告

透明像素合成白底後，取 RGB 色差最大值，大於容許值（預設 16／255）才計為差異。比例為差異像素／兩邊均有內容的有效比較像素，排除忽略區與範圍外像素；無有效像素時回傳 null，不顯示假通過。

JSON schema v3 保留主要舊欄位，新增 `alignment.autoAlignment`，記錄演算法、引擎版本、範圍、倍率來源、人工確認、手動修正、原圖框、匹配指標、區塊驗證與覆蓋比例。`result` 新增 `missing`、`missingReference`、`missingWeb`。v3 的 changed/compared 不再包含缺失像素，報告讀取程式應依 schemaVersion 處理。

套用新裁切或對齊會清除舊比較範圍、忽略框與核准狀態。原始網頁 PNG 和既有回歸基準不會改寫。只靠圖片無法可靠分辨截圖倍率與實作尺寸錯誤；精確驗收仍需設計規格、可信參考尺寸及 computed styles。

## B．後續回歸測試

B 分頁可下載 Playwright 範本，也可使用 [regression/](regression/README.md)。流程是「固定環境擷取候選 → 人工驗收並核准 → 後續自動檢查」。不會自動更新基準。

Playwright 在能存取受測網站的本機或內網環境執行，GitHub Pages 只提供靜態工具。固定瀏覽器、字型、畫面尺寸、縮放、資料及作業系統。A 的像素忽略區不會自動轉成 B 的 DOM selector。

## 部署與維護

一般使用不需 Node.js。部署時保留 `index.html`、`vendor/` 及 `.nojekyll` 的相對路徑，支援 GitHub Pages 子路徑。也可直接將 offline.html 作為單檔入口。

維護者使用 Node.js 20+，修改 src 後執行：

```sh
npm run build
npm test
```

產出網站版 index.html 與內嵌引擎的 offline.html。瀏覽器測試需另備 Playwright 及 Chrome，可透過 PLAYWRIGHT_MODULE 指定既有套件、BROWSER_CHANNEL 選擇瀏覽器：

```sh
npm run test:browser
```

測試使用生成的 UI 圖片，涵蓋 0.25～4 倍、1660×860、角點精度、重複候選、真實差異、部分覆蓋、重排拒絕、取消／換圖、離線與 HTTP、報告、裁切及貼上。合成圖的 2 像素精度驗收不代表所有真實截圖都能達成。

每張圖最多 12 MB、12 百萬像素，合成畫布也受像素上限限制。搜尋放在可取消的 Worker，90 秒逾時後提示縮小搜尋範圍。原圖、Canvas 與 OpenCV 需多份記憶體，長頁面建議分區。
